# Ревизия PR / ветки

Проведи полную многоступенчатую ревизию, но ограничь анализ изменёнными файлами.

**Определи diff:**

```bash
git diff --name-only main...HEAD
git diff main...HEAD
```

Если пользователь указал другую base-ветку — используй её.

**Алгоритм:**

1. Загрузи skill `review-orchestrator`.
2. Определи список изменённых файлов через `git diff --name-only`.
3. Вызови всех семерых reviewer-agents, но каждому передай ТОЛЬКО изменённые
   файлы и их непосредственный контекст (файлы, которые они импортируют/от
   которых зависят, если это важно для понимания находки).
4. Каждую находку привязывай к конкретной строке diff.
5. Сохрани отчёт в `REVIEW_REPORT.md`, пометив в Executive summary, что это
   ревью PR/ветки, а не всего проекта.
6. В чат — Executive summary + топ-5 действий.
