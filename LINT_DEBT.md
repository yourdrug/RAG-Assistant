## Временные исключения

Строгие правила сохранены. Исключения ограничены существующими файлами,
кодами правил Ruff и конкретными связями импорта. Новые файлы продолжают
проверяться строго. В уже перечисленных файлах новые нарушения того же
правила Ruff, новые ошибки mypy и новые замечания форматирования могут быть
скрыты до удаления исключения. Это временное послабление, а не исправление долга.

| Проверка | Где находится исключение | Как вернуть проверку модуля |
|---|---|---|
| Ruff | `server/ruff-baseline.toml`, `[lint.extend-per-file-ignores]` | Удалить строки файлов нужного модуля |
| Ruff format | `server/ruff-baseline.toml`, `[format].exclude` | Удалить пути файлов нужного модуля |
| mypy | `server/pyproject.toml`, блок с комментарием `Temporary file-specific mypy baseline` | Удалить имена модулей из массива `module` этого блока |
| Пустые строки | `server/blank-lines-baseline.txt` | Удалить пути файлов нужного модуля |
| import-linter | `server/pyproject.toml`, `ignore_imports` DDD-контракта | Удалить исправленные связи; устаревшие связи вызывают ошибку |
| deptry | `server/pyproject.toml`, временные элементы `per_rule_ignores` | Объявить реально используемые прямые зависимости / удалить ненужные, затем снять исключения |
| vulture | `server/pyproject.toml`, временные пути `[tool.vulture].exclude` | Проверить кандидатов и удалить пути исправленных файлов |

Для каждого модуля: снять его исключения, исправить замечания, выполнить
`task lint` и относящиеся к изменению тесты. Исключения других модулей
позволяют делать это постепенно. Не добавлять новые файлы в baseline автоматически.

`task fmt` и форматирующие хуки тоже учитывают baseline. Проверка пустых строк
без baseline доступна из `server/` командой
`uv run --group development python tools/blank_lines.py --check app tests tools`.

После полной очистки удалить `server/ruff-baseline.toml`, ссылку `extend` на него,
временный блок mypy, `server/blank-lines-baseline.txt` и аргументы `--exclude-from`
в Taskfile, CI и pre-commit, а также временные исключения import-linter, deptry и vulture.

## Выполненная очистка: application.uow

`application.uow` преобразован в пакет без файловых исключений. Старые модули
`ports/base_uow.py`, `ports/session_protocol.py`, `ports/unit_of_work_factory.py`
оставлены как явные совместимые экспорты и тоже проверяются без baseline.
Удалены четыре записи Ruff, одна mypy, одна проверки пустых строк и две vulture.
Добавлен контракт import-linter, запрещающий UoW зависеть от прежних services,
dto, ports и реализаций внешних слоёв. Исходные числа выше оставлены как снимок.

Проверки: 107 целевых pytest-тестов прошли, включая 18 новых тестов UoW;
все семь проверок из `task lint` выполнены напрямую и прошли. `uv lock --offline`
выполнен; содержимое lock-файла не изменилось. Полный pytest и внешние интеграции
не запускались.
