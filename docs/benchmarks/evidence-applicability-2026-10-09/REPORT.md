# Проверка применимости evidence — 9 октября 2026

**Baseline не принят.** Защита цитат внедрена; quick-30 выполнен. В исходном наборе проверок есть два ожидания ответа без идентичности таблицы, а judge возвращает correctness только для 4 из 30 вопросов. Неизвестные оценки и расходы не заменяются нулём.

## Что изменилось

Доменная проверка возвращает `complete`, `partial`, `insufficient` или `conflict`. Этапы процедуры проверяются по запрошенному акту, документу/редакции, участнику и собственному условию этапа. Два фрагмента хранения не подтверждают отгрузку. Режим передачи должен подтверждаться для запрошенных сведений, категории товаров, EDI-провайдера грузоотправителя и МНС; полное название Министерства и сокращение распознаются одинаково.

Табличная строка проверяется по номеру таблицы, типу сообщения (включая ЭТН/ЭТТН), номеру и полному названию поля. Запрошенный акт и несовместимые версии проверяются отдельно. Для сопоставления поправки с консолидированным документом требуется явная связь «Внести … постановлением N … следующие изменения» в той же редакции поправки. Номер таблицы восстанавливается только из непрерывной цепочки чанков одной таблицы и редакции. Связь режима с категорией товаров восстанавливается по явной цепочке «пункт → приложение → категория», а не по похожести поиска. Все дополнительные чтения проходят через ACL-порт.

Недостаточное evidence выдаёт детерминированный ограниченный ответ или отказ. Обычная генерация LLM не получает эти вопросы для догадки. Статус/обязательность поля также требуют явной операции замены; два значения сами по себе не доказывают историю изменения. Политика cache key обновлена до `2026-10-09-applicability-v6`.

## Quick-30 и измерения

Параметры run 12 сохранены: top-k 8, fetch-k 30, sparse weight 0.5, cache off, параллельность 2. Generation и judge: `qwen/qwen-2.5-7b-instruct`. Текущая конфигурация БД выбирала 72B; для сравнения 7B закреплена только в процессе benchmark, без изменения БД. Исторические runs 11/12 и публичный baseline не перезаписаны. Сохранены ранее подготовленные общие критерии judge и веса качества: faithfulness 0.4, correctness 0.3, hit-rate 0.2, relevancy 0.1.

Полный запуск сохранён: **30 generated / 30 evaluated**. Оценка выполнена после генерации по сохранённым ответам. «30 evaluated» не означает наличие всех оценок: faithfulness/relevancy доступны 30/30, correctness — **4/30**. Повторные ответы judge, не прошедшие валидацию, входят в usage/cost.

Сумма времени запросов при параллельности 2 отличается от времени запуска по часам. RAG измеряется вокруг полного `invoke`, включая retrieval, selection, relevance и generation/refusal; время judge и запуска приложения исключено.

Из 266 внешних model-вызовов стоимость 222 известна из ответов API: $0.05993102. Для 44 embedding-вызовов API сообщает токены, но не стоимость: 1252 токена оценены как $0.00001252 по [тарифу DeepInfra BAAI/bge-m3](https://deepinfra.com/BAAI/bge-m3) — $0.01 за миллион токенов, проверенному 09.10.2026. Итого выше — **полная оценка внешних API для финальных 30 случаев**, не сумма счёта провайдера. Hosting/локальный compute, прежние экспериментальные прогоны и невидимые transport-retries исключены. Неизвестная фактическая embedding-стоимость остаётся `null`; `cost_complete=false`.

Для streaming OpenRouter сохраняются raw usage/cost/generation ID до того, как LangChain их отбрасывает. Usage охватывает auxiliary calls, embeddings, reranking, generation и judge. Неудачные generation/judge-попытки сохраняют наблюдавшийся usage; sibling-задачи завершаются до освобождения ресурсов. Resume требует одинаковых input fingerprint, source-run, моделей, политики и параметров поиска.
