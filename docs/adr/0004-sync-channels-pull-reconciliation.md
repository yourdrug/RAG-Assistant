# ADR 0004: синхронизация документов из GitHub — pull-сверка через GitHub App

Статус: принято, не реализовано.

Документация проектов лежит в GitHub (локально — github.com, в закрытом контуре — GitHub
Enterprise Server) и должна поддерживаться в RAG без полной перезагрузки. Мы выбрали
**pull-сверку**: вебхук GitHub App лишь запускает прогон, сервер сам разрешает ветку в коммит,
читает полное дерево этого коммита и применяет разницу с опубликованными ревизиями документов
по `blob_sha`. Содержимому вебхука не доверяем; пропущенные вебхуки подбирает периодическая
сверка. Владельцы репозиториев в основном не технические специалисты, а App устанавливается
админом один раз на организацию — в репозиториях ничего настраивать не нужно.

## Отвергнутые варианты

- **Action присылает `git diff`.** Ломается при пропущенном прогоне, force-push и сбое запроса —
  RAG навсегда расходится с репозиторием.
- **Push-протокол с манифестом и ключом канала.** Идемпотентен, но требует workflow в каждом
  репозитории. Модель канала его допускает; реализуем, когда появится внешний клиент без
  доступа сервера к хранилищу.
- **Fine-grained токен на канал.** Требует ручной настройки вебхука владельцем и не доказывает,
  что создатель канала вправе публиковать репозиторий.

## Последствия

- Удаление документов допустимо только после полностью прочитанного снимка одной ревизии;
  при недоступности ветки или неполном обходе документы канала сохраняются.
- App видит все репозитории установки, поэтому привязку репозитория и любое расширение охвата
  канала (папка, ветка, исключения, аудитория) одобряет только админ.
- Серверу нужен исходящий доступ к GitHub API; адрес задаётся статической конфигурацией и
  входит в allowlist, ключ App — только в env.
- Всё, что зависит от хранилища (ревизия, список файлов, версия файла, чтение, ссылка), скрыто за
  одним портом снимка; GitHub — первая реализация, pull-S3 и push — следующие (паттерн «Стратегия»).
  Сверка, права и удаление общие.
- Владельцы хранилища исключают файлы из индекса через `.ragignore` (синтаксис `.gitignore`) без
  участия админа. Он только сужает одобренный охват, читается из той же ревизии и не участвует
  в проверке пересечения каналов; нечитаемый `.ragignore` останавливает прогон без изменений.
