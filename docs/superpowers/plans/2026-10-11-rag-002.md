# RAG-002: ingestion object identity implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement the tasks in order.

**Goal:** Index S3 objects with identical basenames independently, using the complete object key without the bucket.

**Architecture:** Registry identity is `object_key`; `filename` remains the original basename and `source` remains the existing S3 URI. Documents persist an optional `ingestion_key` separately from their storage path and display filename. Creation commits that binding before content sync, so a retry after registry persistence fails reuses the document. Existing filename uniqueness and ACL transaction boundaries remain in force.

**Tech Stack:** Python, SQLAlchemy, PostgreSQL, Alembic, pytest.

**Spec:** Agreed design in this conversation: full object key, one configured bucket, unique display aliases for SQL filename collisions, durable document binding, post-sync registry persistence, migration and regression coverage. RAG-001 is excluded.

## Global constraints

- Domain cannot import application/infrastructure/presentation/config; application cannot import infrastructure/presentation.
- No new dependencies, nested production imports, production assertions, or new functions with leading underscores.
- Preserve existing owner/group ACL handling, including confirmed ownerless legacy ingestion conversion.
- Do not use `source_path` for identity: it governs storage deletion and rename.
- Commit and push only this change; leave existing untracked project files alone.

## Review focus

- Equal basenames and equal size/mtime must remain independent.
- Keys containing spaces, Unicode, `?`, `#`, and repeated slashes must retain exact identity.
- Registry-write failure must not create an extra document on retry.
- Concurrent creates require database uniqueness and bounded whole-transaction retries.
- Legacy registry migration must stop on ambiguous document bindings instead of guessing; downgrade must stop if duplicate basenames cannot be represented.
